Thesis prototype · City of Baguio

Waste Collection Route Optimizer

A decision-support tool that compares a garbage truck's usual collection order with an optimized order on Baguio's real road network, and shows how much distance, time, fuel, cost and CO₂ the better order saves.

Sample route, 10 collection points 37.2% shorter

Press → or Space for the next slide, ← to go back, F for full screen.

The question

If the truck visited the same stops in a better order, how much would it save?

Collection crews often follow a habitual stop order. The system keeps everything else fixed, so the comparison isolates the effect of the order itself.

Same truck

One vehicle with the same speed, fuel efficiency, fuel price and CO₂ factor for both routes.

Same stops

The garage and every collection point are identical. The truck leaves the garage and returns to it.

Same roads

Both routes drive on Baguio's OpenStreetMap road network with the same pathfinding. Only the visiting order differs.

What the system does

Four steps from a list of stops to a comparison

  1. Load the stops

    Upload a route file, or tap the garage and stops directly on a map of Baguio.

  2. Check the data

    Six validation checks run before anything else, in the browser and again on the server.

  3. Build both routes

    A simulated traditional route and an optimized route, each on real drivable roads.

  4. Compare and export

    Distance, travel time, fuel, cost and CO₂ side by side, plus maps and files for the manuscript.

Input

Two ways to enter a route

Data quality

Nothing runs until the route passes six checks

  • Schema versionOnly version 1.0 files are accepted.
  • MetadataRoute name, study area, vehicle, driver and date are present, and vehicle numbers are valid.
  • GarageThe start and end point has an ID, name, latitude and longitude.
  • Collection pointsAt least one point, each with the same four required fields.
  • CoordinatesLatitude between −90 and 90, longitude between −180 and 180.
  • DuplicatesNo repeated point IDs or coordinates, and no point reuses the garage ID.

The same validation engine gives instant feedback in the browser and is enforced again on the server. After the run, any stop more than 300 m from a drivable road is flagged as a warning.

How a run works

Seven stages, shown live as the run progresses

  1. 1ValidateSix checks, enforced on the server
  2. 2Road networkBaguio's drivable OpenStreetMap roads: 47,388 nodes, 93,012 edges, cached after the first download
  3. 3Snap stopsEach stop is matched to its nearest road node
  4. 4Traditional routeStops in their original order, roads found with A*
  5. 5Optimized routeStops ordered with Christofides TSP, roads found with A*
  6. 6EvaluateDistance, time, fuel, cost and CO₂ for both
  7. 7ArchiveEvery run is saved and can be reopened from History

Algorithms

Two algorithms, each with one job

Christofides TSP Decides the order

Solves the travelling-salesman problem over the stops: which order visits every collection point once and returns to the garage with the least road distance.

Input
Road distances between every pair of stops, computed with Dijkstra on the road network.
Quality
At most 1.5× the shortest possible tour. The prototype keeps this guarantee for routes of up to 21 stops including the garage.

A* search Finds the roads

Finds the shortest drivable path between two consecutive stops, street by street.

Heuristic
Straight-line (great-circle) distance to the next stop, which guides the search without skipping the true shortest path.
Road rules
Runs on the directed road graph, so one-way streets are respected.
Traditional routeOriginal stop order+A* roads
Optimized routeChristofides stop order+A* roads

Both routes use the same A* pathfinding, so any difference in the results comes from the stop order.

Output

What the panel sees after a run

  • Savings tiles for distance, time, fuel cost and CO₂, each with both values.
  • Route map with the optimized route in green and the traditional route dashed in blue. Either layer can be hidden.
  • Visiting order list. Selecting a stop zooms the map to it.
  • Comparison, Route details and Road network tabs with the full tables and the snapped node of each stop.
  • Export to CSV, JSON and GeoJSON for spreadsheets and GIS software.
  • History keeps every run so it can be reopened later.

Scope

What the prototype models, and what it leaves out

Modelled

  • Baguio City's drivable roads from OpenStreetMap, including one-way streets
  • One truck per run that starts and ends at the garage
  • Distance, travel time, fuel, fuel cost and CO₂ for both routes
  • Vehicle values from the route file, or the defaults

Not modelled

  • Traffic, road slope and time spent loading at each stop (one average speed)
  • Truck capacity, multiple trucks and collection time windows
  • Areas outside the Baguio study area
  • A guaranteed optimal order. Christofides is an approximation.

The results are estimates for comparing two stop orders, not dispatch instructions.
